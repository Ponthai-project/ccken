# Graph Engineering 解説資料（グラレコHTML）の作成

## 1. 背景と経緯

「Graph engineering に関する解説資料をグラレコ調のアーティファクトで出力せよ」という依頼を受けた。
原文（元記事・登壇資料）の指定はなく、テーマ名のみが与えられた案件である。したがって本件は
「既存文書の図解化」ではなく「対象領域を自分で構成し直す解説の新規執筆」であり、
`graphreco-html` skill の想定するワークフロー（原文の正確な調査→図解設計）のうち、
第2工程の性質が通常案件と異なる点が最初の論点となった。

作業場所は途中で殿より `personal_doc/` 配下と指定された。

## 2. 決めるべきだったこと

1. 「Graph engineering」をどの文脈で解釈するか（総合／AI・LLM／データ基盤／機械学習）
2. 読み手の想定レベル
3. グラレコのティアA（軽量・その場完結）かティアB（手描きフォント埋め込み）か
4. 原文が無い案件で「事実正確性」をどう担保するか
5. 本文フォントに Google Fonts を使うか、skill 規約の「外部参照ゼロ」を優先するか
6. 図解7型をどう割り付け、狭幅時の矢印の向き変更をどう実装するか
7. 実作業を配下（subagent）に委任するか、信玄が直接執筆するか

## 3. 検討した選択肢

### 論点1・2・3（殿に確認）

いずれも解釈次第で成果物が大きく変わるため、着手前に AskUserQuestion で確認した。
結果：**総合（技術全体を俯瞰）× エンジニア（グラフは未経験）× ティアA**。

### 論点4：事実正確性の担保

- **案A：記憶ベースで書き、出典を付けない** → skill の事実裁定条項に反する。却下。
- **案B：具体的なベンチマーク数値を出す** → 「RDBの深いJOINに対しグラフDBは何倍速い」といった
  数値は文献ごとに条件が違い、記憶からの再現は捏造の危険が高い。却下。
- **案C（採用）：規格番号・論文・OSS の一次情報に限って固有名詞と年を出し、性能は数値ではなく
  「深さに対して指数的（RDB）／おおむね一定（グラフ）」という関係の形で書く。**
  出典URLはフッターに列挙し、「特定記事の要約ではない」旨を明記する。

### 論点5：フォント

- **案A：Google Fonts（Zen Maru Gothic / Zen Kurenaido）を `<link>` で読む。** Artifact の CSP は
  Google Fonts のみ例外的に許可しており、丸ゴシック＋手書き系の対比で手描き感が強く出る。
- **案B（採用）：`<link>` を撤去し、skill の CSS骨格が実機検証済みとしている
  `Candara → UD Digi Kyokasho N → Yu Gothic → sans-serif` に戻す。**

### 論点6：狭幅時の矢印

- **案A：`transform:rotate(90deg)` で横矢印を倒す**（css-skeleton の `.flow-arrow-wrap` と同じ手法）。
- **案B（採用）：縦向きシンボル `hand-arrow-down` を新設し、メディアクエリで表示を差し替える。**

### 論点7：委任

- **案A：CLAUDE.md の原則どおり高坂（設計・文書）へ委任する。**
- **案B（採用）：信玄が直接執筆する。**

## 6. 検証の結果（実機・レンダリング）

`render_html.py` で全ページをレンダリングし、目視検分した。**論理的推論ではなく実機確認である。**

機械確認：C1 図解11／節11で一致、C2 型指定は7語のみ11件、C3 相異なる型6種・場面1件（上限3.67以内）、
C6 `<use href=` 55件 ≧ 33件、C7 `<text` 0件で `fig-label` と一致、C8 `.fig-block` 内の
40〜59px幅なし・`rotate(` 0件、外部参照0件、`feTurbulence` 4帯定義・帯の取り違えなし。

目視で発見し修正した崩れ：

1. **位置づけ図のY軸ラベルが横並びになった**（04・11）。親要素に `writing-mode:vertical-rl` を掛けると
   flex の主軸まで横になり、`flex-direction:column` が効かなくなる。各 `span` 側に移して解決。
2. **X軸ラベルが図解キャプションと重なった**（04・11）。軸ラベルを `bottom:-26px` で枠外に出しており
   高さ計算に入らないため。`.fig-map` に下マージンを付けて解決。
3. **06 の枝が3列＋1列になり下段に空白が出た**。`auto-fit` をやめ2列固定にして2×2に。
4. **11 の丸囲みがラベル文字を横切っていた**。`inset` の下端を負値にして全体を囲むよう修正。
5. 11 のキャプションが「丸で囲んだ領域」と書いていたが実際に囲んでいるのは1点のみだったため、
   文言を実態に合わせた（図に合わせて文を直す方向で解消し、図の側を水増ししない）。
