CLAUDE CODE — 設定・拡張機構の見取り図

CLAUDE.md / settings.json /
.claude/rules/ / Skills

4つとも「Claude Codeの挙動を変える」点は同じ。
でも何を書くかといつ効くかが違う。

「まず読み込まれ方の違いから見ていくのじゃ。起動時に自動で乗るのは3つ。Skillsだけは名前で呼ばれるまでコンテキストに乗らないぞ」
01
起動時、何が自動的に読み込まれるか

下の3つは呼び出さなくても毎回自動で効く。Skillsだけは名前で呼ばれるまでコンテキストに乗らない。

常時オート・ロード
MD

CLAUDE.md

自然言語の指示・プロジェクトの前提知識。人間向けの説明書きをそのまま読ませる。

JSON

settings.json

権限・フック・MCP・モデル選択などハーネス自体の構造化された挙動設定。

RULE

.claude/rules/*.md

ディレクトリ・パス単位で切り替えたい規約。触っている場所によって効く内容が変わる。

すべて合成 → 「今のセッションの前提・制約・作法」として常にコンテキストに存在
オン・デマンド（呼ばれたときだけ）
SKILL

.claude/skills/*/SKILL.md

「この作業のやり方」を手順化したもの。/skill-name で明示的に呼ぶか、内容が今の作業に合致した時だけ読み込まれる — 常駐しない分、平時のコンテキストを圧迫しない。

02
詳細比較

形式・優先順位・向いている内容の違いを一覧で見る。

機構目的発火タイミング適用範囲書くのに向く内容
MDCLAUDE.md プロジェクト／ユーザーの恒久的な前提知識・方針を伝える セッション開始時に自動ロード。ディレクトリ階層ごとに重ねがけ グローバル(~/.claude/)〜プロジェクト〜サブディレクトリ コーディング規約、アーキテクチャ方針、ロールプレイ設定など言葉で説明する指示
JSONsettings.json ハーネス自体の動作を構造化データで制御する セッション起動時にマージして自動適用 Enterprise管理 > CLI引数 > プロジェクトlocal > プロジェクト > ユーザー 権限許可リスト、フック、環境変数、MCPサーバー登録、モデル指定など設定値
RULE.claude/rules/ 触っているパスに応じて適用ルールを出し分ける 該当パスを扱う操作時に自動的に効く パス単位（ディレクトリ別に細分化） 「frontend/配下ではこの規約」のような場所依存の細則
SKILLSkills 特定タスクの手順・ワークフローを再利用可能にパッケージ化する 名前で明示的に呼ぶ、または内容が状況に一致した時のみ読み込み プロジェクト／ユーザー（配置場所による） 「デプロイ手順」「レビュー手順」など再利用する一連の作業手順

4つの違いは結局「常時か・オンデマンドか」と「言葉の指示か・構造化データか」の掛け算で整理できる。CLAUDE.mdとrulesは同じ自然言語の指示だが、rulesはパスという条件つきで発火する点がCLAUDE.mdと違う。settings.jsonだけがハーネス自体の構造化設定であり、優先順位（Enterprise管理 > CLI引数 > プロジェクトlocal > プロジェクト > ユーザー）まで明確に決まっている。

03
結局どこに書けばいいか

4つの「こう動いてほしい」から逆引きする。

「毎回この方針で動いてほしい」
CLAUDE.md
「このコマンドは毎回許可して」「このフックを仕込みたい」
settings.json
「このディレクトリ配下だけ別ルールにしたい」
.claude/rules/
「この一連の作業を使い回したい・名前で呼びたい」
Skills
常時ロード3種（CLAUDE.md／settings.json／rules）は指示が積み重なるほどコンテキストを消費する。パス限定の話は rules/ に、手順化できる作業は Skills に逃がすと運用が軽くなる。
