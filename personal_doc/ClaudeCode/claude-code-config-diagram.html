Claude Code — 設定・拡張機構の見取り図

CLAUDE.md / settings.json / .claude/rules/ / Skills

4つとも「Claude Codeの挙動を変える」点は同じだが、何を書くものかといつ効くかが異なる。まず読み込まれ方の違いから見る。

起動時、何が自動的に読み込まれるか

下の3つは呼び出さなくても毎回自動で効く。Skillsだけは名前で呼ばれるまでコンテキストに乗らない。

常時オート・ロード

MD

CLAUDE.md

自然言語の指示・プロジェクトの前提知識。人間向けの説明書きをそのまま読ませる。

JSON

settings.json

権限・フック・MCP・モデル選択などハーネス自体の構造化された挙動設定。

RULE

.claude/rules/*.md

ディレクトリ・パス単位で切り替えたい規約。触っている場所によって効く内容が変わる。

↓ すべて合成される
今のセッションの前提・制約・作法として常にコンテキストに存在

オン・デマンド（呼ばれたときだけ）

SKILL

.claude/skills/*/SKILL.md

「この作業のやり方」を手順化したもの。/skill-nameで明示的に呼ぶか、内容が今の作業に合致した時だけ読み込まれる — 常駐しない分、平時のコンテキストを圧迫しない。

結局どこに書けばいいか

「毎回この方針で動いてほしい」CLAUDE.md

「このコマンドは毎回許可して」「このフックを仕込みたい」settings.json

「このディレクトリ配下だけ別ルールにしたい」.claude/rules/

「この一連の作業を使い回したい・名前で呼びたい」Skills

常時ロード3種は指示が積み重なるほどコンテキストを消費する。パス限定の話はrules/、手順化できる作業はSkillsに逃がすと運用が軽くなる。
